# Относительный путь к образу не находится

## Что происходит

```python
mk.stlink.flash(r"templates\counter_l0\backup_....bin", addr=0x08000000)
```

при относительном пути и текущем каталоге, где файл реально лежит:

```
Error: The file backup_....bin does not exist, please check the file's path
```

## Почему

`mcukit.stlink.run()` запускает `STM32_Programmer_CLI.exe` с `cwd=job` —
рабочей папкой задания (`env.new_job_dir`), как и `mcukit.jlink.run()`.
Относительный путь к файлу-аргументу (`-d <image>`, `-u ... <file>`)
разрешается CLI относительно этого `cwd`, а не относительно каталога, из
которого запущен Python.

## Как правильно

Приводить путь к образу и к файлу upload/download `os.path.abspath()`
перед передачей в аргументы CLI. В `mcukit.stlink.flash()` это сделано
(`image = os.path.abspath(image)`); `save()` не подвержена — путь
назначения строится через `env.new_job_dir()`, уже абсолютный.

## Как неправильно

Передавать в `flash()` путь, каким его дал пользователь или другая
функция (`mk.build()` возвращает абсолютные пути — тогда проблемы нет;
проблема — с путями, собранными вручную или относительными).

## Чем подтверждено

`mk.stlink.flash()` с относительным путём — ошибка CLI `does not exist`;
после правки (`os.path.abspath` в начале функции) тот же вызов с тем же
относительным путём отработал и записал образ.
