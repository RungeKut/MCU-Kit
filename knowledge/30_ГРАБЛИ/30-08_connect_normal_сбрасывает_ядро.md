# `connect` по умолчанию сбрасывает ядро

## Что происходит

Прошивка с растущим в ОЗУ счётчиком (`knowledge/20_ПРИЁМЫ/20-02`),
несколько подключений подряд с интервалом 0,5 с, `-c port=SWD` без
`mode=`:

```
loop_count: 0xcda0f6, 0x2a769, 0x2b44b, 0x2a514, 0x2b3b1, 0x2a174
```

Первое значение большое (устройство успело поработать до подключения),
но дальше счётчик не растёт монотонно — прыгает в районе 170–180 тысяч
туда-сюда. То же самое обращение с `mode=HOTPLUG`:

```
loop_count: 0x7d5f49, 0x817cce, 0x85801f, 0x89a6a3, 0x8daa50
```

растёт монотонно, разница между чтениями стабильна (~263–272 тысячи за
0,5 с). Вывод `-c` одинаков в обоих случаях, кроме строки `Connect mode`:
`Normal` против `Hot Plug`.

## Почему

`--help` описывает у `-c` два разных под-параметра: `mode=` (`UR` /
`HOTPLUG` / `NORMAL`, умолчание `NORMAL`) и `reset=` (`SWrst`/`HWrst`/
`Crst`, умолчание `SWrst`). По документации это выглядит как «тип
сброса, если он вообще происходит», но на практике `mode=NORMAL`
выполняет этот сброс (`SWrst`) на каждое подключение, а не только когда
явно запрошен `-rst`. `mode=HOTPLUG` — единственный проверенный способ
присоединиться, не трогая состояние ядра.

## Как правильно

* Для функций, которые не должны иметь побочных эффектов на работающей
  плате (`info`, `read32`, `watch`, `save`) — всегда `mode=HOTPLUG`
  (в `mcukit.stlink` это значение по умолчанию с 25.09.2026).
* Для `flash()`/`reset_run()`, которым сброс и нужен, — обычный
  `mode=NORMAL` можно оставить как есть.
* Проверять именно поведением (счётчик, который не должен обнуляться),
  а не текстом вывода: строка `Device ID` присутствует в обоих режимах,
  разница видна только в поведении цели.

## Как неправильно

Полагаться на `-c port=SWD` без `mode=` как на «пассивное подключение» —
такое предположение выглядело правдоподобным по аналогии с J-Link
(`mem32` не трогает ядро, `10-01`) и было ошибочно записано в первой
версии `mcukit.stlink` без проверки живым счётчиком; статическое чтение
(значения, не менявшиеся между подключениями) эту ошибку не ловит,
потому что сброс просто восстанавливает то же самое статическое
содержимое.

## Чем подтверждено

`mk.stlink.watch()` c `loop_count` — тестовая прошивка без обращения к
периферии (`templates/counter_l0`), плата со STM32L07x, ST-LINK/V2, 6
подключений с `mode=NORMAL` (умолчание) и 5 с `mode=HOTPLUG` подряд,
интервал 0,5 с.
