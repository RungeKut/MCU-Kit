# binutils и кириллица в пути

## Что происходит

```
arm-none-eabi-nm "Y:\...\<папка с кириллицей>\build\app.elf"
arm-none-eabi-nm.exe: 'Y:\...\<папка с кириллицей>\build\app.elf': No such file
```

Код 1, stdout пуст. `size` — так же. Сборка при этом прошла: make и gcc
работали в рабочей папке без кириллицы, а сюда ELF только скопирован.

## Почему

Не выяснено. Путь в сообщении об ошибке напечатан целым, в cp1251, —
до утилиты он дошёл, а открыть файл она не смогла. Пробелы ни при чём:
относительный путь из той же папки работает, хотя папки выше содержат и
пробелы, и кириллицу.

## Как правильно

`mcukit.size()` и `mcukit.symbol()` копируют файл с таким путём в
рабочую папку и зовут утилиту над копией. Руками — запускать из папки
файла с относительным путём (`nm build\app.elf` работает).

## Как неправильно

Решить по пустому выводу `nm`, что символа нет: исключение «символ не
найден» было ложным.

## Чем подтверждено

`nm` по абсолютному пути — код 1; из той же папки с относительным путём —
код 0, 499 байт вывода; через `mcukit.symbol` — адрес найден, `watch`
показал растущий счётчик.
