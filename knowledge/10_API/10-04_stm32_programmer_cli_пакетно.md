# STM32_Programmer_CLI.exe пакетно

## Что происходит

В отличие от J-Link Commander (`10-01`), у CLI нет файла сценария с
несколькими командами и паузами: один запуск — одно подключение и одно
действие. Типичный вызов:

```
STM32_Programmer_CLI.exe -q -log <path> -c port=SWD [freq=<кГц>] [sn=<SN>] \
    -r32 <адрес> <размер_в_байтах>
```

Подключение (`-c port=SWD ...`) само по себе печатает блок с серийником
зонда, напряжением и данными ядра:

```
ST-LINK SN  : H
ST-LINK FW  : V2J32S7
Voltage     : 3.27V
Device ID   : 0x447
Device name : STM32L07x/L08x/L010
Flash size  : 128 KBytes
Device CPU  : Cortex-M0+
```

Чтение (`-r8`/`-r16`/`-r32 <адрес> <размер>`) — размер в **байтах**, не в
словах. Вывод по 4 слова в строке:

```
0x20000000 : 00000001 00000003 00001D20 01E84800
0x20000010 : 00010100 43FA0000 42C80000 3F800000
```

## Почему

CLI спроектирован как последовательность независимых команд в одном
запуске (`-c ... -r32 ... -rst`), а не как интерпретатор сценария — отсюда
и отсутствие пауз внутри сеанса.

## Как правильно

* Собирать аргументы списком (`subprocess`, без `shell=True`), а не одной
  строкой: под-параметры `-c` (`port=`, `freq=`, `sn=`) — отдельные
  элементы списка, не одна склеенная строка.
* Успех подключения — по наличию строки `Device ID` в выводе, а не по
  коду возврата (`30-07`) и не по одному отсутствию строк `Error:`.
* `-q` не убирает шапку с версией и строку `Log output file:` — парсить
  построчно регулярным выражением, не проверять вывод целиком.
* `-log <path>` пишет подробный журнал рядом со stdout — берётся после
  тайм-аута, как у J-Link (`10-01`).

## Как неправильно

Судить об успехе по коду возврата: он равен 1 даже при удачном
подключении, если указан `sn=` (`30-07`).

## Чем подтверждено

`-c port=SWD`, `-r32 0x20000000 32`, `-u 0x20000000 64 <file>` — плата с
STM32L07x, зонд ST-LINK/V2 (FW V2J32S7), STM32CubeProgrammer 2.4.0.
`-d`/`-v`/`-rst` — не запускались, синтаксис из `--help` (`40-03`).
