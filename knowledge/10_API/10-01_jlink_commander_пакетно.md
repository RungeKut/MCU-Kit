# J-Link Commander в пакетном режиме

## Командная строка

```
JLink.exe -NoGui 1 -ExitOnError 1 -device <имя> -if SWD -speed 4000
          -log <папка>\jlink.log -CommandFile <папка>\cmd.jlink
          [-USB <серийный номер>]  [-jtagconf -1,-1  — для JTAG]
```

* `-device` — профиль: `Cortex-M4` (только ядро, скрипта производителя
  нет) или имя чипа (`GD32F470VK`, нужно для загрузчика флеша). Почему
  начинать с ядра — [20-01](../20_ПРИЁМЫ/20-01_порядок_первого_подключения.md).
* stdin — закрыть (`subprocess.DEVNULL`): J-Link, если спросит с консоли,
  получит конец ввода и не повиснет. Но сценарий при этом молча
  оборвётся — [30-05](../30_ГРАБЛИ/30-05_jlink_молча_обрывает_сценарий.md).
* Файл команд — ASCII, по команде на строку, в конце `qc`. Пути в
  командах — без пробелов и кириллицы (mcukit копирует файлы в рабочую
  папку).
* `-ExitOnError 1` — после первой ошибки остальные команды не
  выполняются, код возврата 1.

## Команды, которыми пользуется mcukit

| Команда | Что делает |
|---|---|
| `ShowEmuList`, `usb`, `st` | зонды; подключиться к зонду; VTref и уровни линий — к чипу не подключается |
| `connect` | подключиться к ядру; не останавливает и не сбрасывает |
| `mem32 <адрес> <n>`, `mem16`, `mem8` | чтение; работает и на бегущем ядре |
| `h`, `g`, `r` | остановить, пустить, сбросить (с остановкой) |
| `sleep <мс>` | пауза внутри сценария |
| `loadbin <файл> <адрес>` | записать .bin во флеш; сравнивает, стирает, пишет и проверяет только изменившиеся секторы |
| `verifybin <файл> <адрес>` | сверить флеш с файлом: `Verify successful.` |
| `loadfile <файл>` | .hex/.elf/.srec, адреса из файла |
| `savebin <файл> <адрес> <размер>` | сохранить память в файл |

## Как понять, что сеанс удался

Код возврата — **не** признак: при молчаливом обрыве сценария он 0
([30-05](../30_ГРАБЛИ/30-05_jlink_молча_обрывает_сценарий.md)). Проверяется:

1. каждая команда есть в эхе `J-Link>команда` (`Result.skipped` пуст);
2. нет строк `Error occurred`, `Could not connect`, `Verify failed`;
3. для записи — `O.K.` после `loadbin`/`loadfile` и `Verify successful.`
   после `verifybin`;
4. для подключения — `Found Cortex-M4 r0p1` и `Cortex-M4 identified.`

Вывод приходит в stdout только при выходе процесса. Убитый по тайм-ауту
J-Link не оставляет в stdout ничего, а журнал `-log` к этому моменту уже
записан — по нему и разбираться.

## Чем подтверждено

`mcukit.run`, `probe`, `info`, `read32`, `watch`, `save`, `flash` на плате с
GD32F470: 16 КБ, сохранённые `savebin`, совпали с записанным образом, хвост
— `0xFF`. `connect` по JTAG через переходник без TDI дал `Could not
connect`, код 1, `mem32` в эхе отсутствует.
