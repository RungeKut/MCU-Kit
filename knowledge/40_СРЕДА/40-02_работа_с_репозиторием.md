# Работа с репозиторием

Набор живёт в `https://github.com/RungeKut/MCU-Kit` и разворачивается
на нескольких машинах.

## Обязательный порядок

```bash
cd "$MCUKIT_HOME"
git pull --rebase                                        # В НАЧАЛЕ работы
# ... правки набора ...
git diff                                                 # прочитать глазами
python tools/check_docs.py --project "<папка проекта>"   # стоп-слова
git add -A && git commit -m "что и почему" && git push   # СРАЗУ после правки
```

Push отклонён — `git pull --rebase`, потом push снова. **После слияния —
проверку заново и перечитать слитое**: git сливает текст, а не смысл.
Соседний набор уже получал так испорченную таблицу индекса: две строки
слились в одну. `check_docs.py` считает ячейки в строках таблиц.

## Подготовка коммита: изделие в набор не попадает

Репозиторий **публичный**. Убирается всё, по чему узнаётся изделие:

* название, децимальный номер, номер платы и схемы, имена файлов проекта;
* обозначения, имена цепей, назначение выводов МК на плате изделия;
* протоколы, команды, адреса и форматы обмена изделия;
* номиналы, корпуса и узлы, если по ним узнаётся плата;
* пути к папке проекта, имена серверов, учётные записи, корпоративные
  адреса почты.

**Остаётся**: поведение инструментов и чипов, командные строки, адреса
служебных регистров из руководств, примеры на отвлечённой «плате с
Cortex-M4» или на отладочных платах. Имя чипа можно: это не примета
изделия.

### Стоп-лист — только локальный

`tools/stoplist.txt` — названия изделий, номера, серверы, учётные записи
этой машины. Он **в `.gitignore` и в репозиторий не попадает**; заводит его
`setup.ps1`, и у каждой машины он свой. Стоп-лист, лежащий в публичном
репозитории, сам публикует то, что должен скрывать, — соседний набор для
SolidWorks так и публиковал названия, пока файл не убрали из репозитория.
Новое изделие — строка в стоп-лист **до** первого коммита.

`check_docs.py` считает ошибкой оба случая:

* файла нет — проверять не по чему (свежая машина без `setup.ps1`);
* файл снова под git — `.gitignore` не мешает вернуть его через
  `git add -f` или слиянием старой ветки. Убрать:
  `git rm --cached tools/stoplist.txt`.

`check_docs.py --project "<папка>"` добавляет к стоп-словам имя папки
проекта и имена лежащих там плат, схем и прошивок (`.brd`, `.dsn`,
`.sch`, `.pcb`, `.hex`, `.elf` и т. п.). Хук `commit-msg` проверяет текст
коммита по стоп-листу и по `git config mcukit.project`. Описание узла, по которому изделие узнаётся
без названия, не ловит ничего — за этим `git diff` глазами.

### Автор коммита — публичный и задан для клона

Публичный репозиторий — публичное имя. В каждом клоне набора автор
задаётся **локально**:

```bash
git config user.name  "<публичное имя>"
git config user.email "<публичный адрес>"
```

Иначе git подставляет глобальные настройки машины — на рабочей машине это
рабочее имя и корпоративный адрес, — и они уходят в публичную историю: в
соседнем наборе для SolidWorks так ушли три коммита. Стоп-лист и хук этого не ловят:
имени автора нет ни в файлах, ни в тексте сообщения. Поэтому
`check_docs.py` отдельно требует автора на уровне клона, а `setup.ps1`
напоминает о нём.

## GitHub без gh

На машине может не быть `gh`. Для публикации хватает git с сохранённым
доступом к github.com (Диспетчер учётных данных Windows) и REST API:

```bash
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')
curl -s -H "Authorization: token $TOKEN" https://api.github.com/user/repos \
     -d '{"name":"MCU-Kit","description":"...","private":false}'
```

**`gh auth login` из агентской оболочки не запускать** — интерактивная
команда без терминала висит вечно. Нет доступа — попросить человека
выполнить вход в своём терминале.

## Установка на новой машине

```powershell
git clone https://github.com/RungeKut/MCU-Kit.git
cd MCU-Kit
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

Затем перезапустить Claude Code: скиллы перечисляются при старте.
