# Микроконтроллеры: сборка и прошивка скриптами

Набор — git-репозиторий, общий для нескольких машин. Корень находится так:
переменная `MCUKIT_HOME`, иначе `~/.claude/skills/mcu` — junction,
ведущий в `<корень>/skill`.

## ОБЯЗАТЕЛЬНО: синхронизация репозитория

**В начале работы — подтянуть изменения.** Первым действием, до работы с
платой и до чтения базы:

```bash
cd "$MCUKIT_HOME" && git pull --rebase
```

Конфликт — разобрать сразу: база знаний важнее текущей задачи.

**В набор не попадает ничего об изделии.** Репозиторий публичный. Ни в
файлах, ни в тексте коммита — ни названия, ни децимального номера, ни
номера платы, ни имён цепей и компонентов, ни назначения выводов МК на
плате изделия, ни протоколов и команд изделия, ни путей, серверов и
учётных записей. Примеры — на отвлечённой «плате с Cortex-M4». Имя чипа
(GD32F470, STM32F407) — можно.

**После каждого изменения набора — отправить.** Сразу, не в конце сессии:

```bash
cd "$MCUKIT_HOME"
git diff                                                # 1. прочитать глазами
python tools/check_docs.py --project "<папка проекта>"  # 2. стоп-слова
git add -A && git commit -m "кратко что и почему"       # 3. текст — тоже
git push
```

Приметы нового изделия вписываются в **`tools/stoplist.txt`** до первого
коммита. Этот файл **локальный**: он в `.gitignore`, его заводит
`setup.ps1`. Не возвращать его под git. Хук `commit-msg` проверяет текст
коммита. Описание узла, по которому изделие узнаётся без названия, не
ловит ничего — за этим `git diff` глазами. Подробности —
`knowledge/40_СРЕДА/40-02`.

**Автор коммитов — публичный, задан для клона** (`git config user.name` и
`user.email` без `--global`). Не задан — не коммитить, а спросить
человека, от какого имени публиковать.

**`gh auth login` из этой оболочки не запускать** — висит без терминала.

## Железо: что можно без спроса, а что нет

* **Без спроса**: `probe()`, `info()`, `read32()`, `watch()` — только
  чтение. `save()` — чтение со стопом ядра на время чтения.
* **Только с согласия человека**: `flash()` и всё, что пишет во флеш или
  в байты настройки; снятие защиты (стирает весь флеш). Перед первой
  записью в плату с неизвестной прошивкой — `save()` старого содержимого.
* **Никогда** не проверять связь профилем чипа (`device="GD32F470VK"`) —
  только `Cortex-M4`: скрипт производителя без связи сам запускает
  стирание (`knowledge/30_ГРАБЛИ/30-02`).
* Питание и проводку делает человек. Не отвечает ядро — сначала спросить
  про **общую землю** и **питание платы**, а не гадать по уровням линий.

## Версии: сверить до начала работы

База собрана на **J-Link V9.38a, GCC 10.3.1, GD32F470**. На других версиях
запись «проверено» читается как «не проверено», пока не подтверждена
(`knowledge/00_ПРАВИЛА.md`, раздел 11).

## Первое действие

```python
import os
import sys
sys.path.insert(0, os.environ["MCUKIT_HOME"])
import mcukit as mk

mk.utf8_console()          # иначе print с кириллицей упадёт
print(mk.jlink_version(), mk.gcc_version())
print(mk.probe())          # зонд, VTref
```

## Рабочий цикл

```python
p = mk.probe()                               # 1. зонд и VTref
i = mk.info(reads=["mem16 0x1FFF7A22 1",     # 2. ядро, профиль Cortex-M4
                   "mem32 0x40023C14 1",     #    защита (GD32F4/STM32F4)
                   "mem32 0x08000000 4"])    #    пуст ли флеш
mk.save(r"D:\проект\old.bin", 0x08000000, 0x10000)   # 3. если не пуст

r = mk.build(r"D:\проект\прошивка").check()  # 4. сборка копией
mk.flash(r.bin, device="GD32F470VK", min_vtref=3.1)  # 5. запись + сверка
mk.watch(mk.symbol(r.elf, "blink_count"))    # 6. растёт — код идёт
```

`flash()` сам повторяет шаги 1–2 и без ответа ядра профиль чипа не
запускает. `min_vtref` — выше порога супервизора питания платы.

## Шесть правил, нарушение которых стоит часа

1. **Порядок подключения — `knowledge/20_ПРИЁМЫ/20-01`.** Зонд → ядро
   профилем Cortex-M4 → состояние → запись профилем чипа.
2. **«Could not connect» — сначала земля и питание.** VTref без общей
   земли показывает правдоподобные 3,2 В (`30-01`); ниже порога
   супервизора ядро в сбросе (`30-03`).
3. **Успех J-Link — по эху команд, а не по коду возврата.** Сценарий
   обрывается молча с кодом 0 (`30-05`); `Result.ok` это учитывает.
4. **«Прошилось» ≠ «работает».** Счётчик в ОЗУ через `watch()`; глазами
   светодиод проверяет человек.
5. **Сборка и binutils — на путях без кириллицы.** `mk.build` и
   `mk.symbol` копируют сами (`30-06`).
6. **Никогда не выдавать непроверенное за проверенное** — ни в коде, ни в
   отчёте, ни в базе знаний.
